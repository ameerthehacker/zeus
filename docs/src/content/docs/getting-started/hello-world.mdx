Time to write your first Zeus program. Zeus source files use the `.zs` extension.

## Your first program

<Steps>

1. **Create a file**

   ```bash
   touch hello.zs
   ```

2. **Write the code**

   ```zeus
   console.log("Hello, World 👋")
   ```

   That's it — no boilerplate.

3. **Run it**

   ```bash
   zeus run hello.zs
   # Output: Hello, World 👋
   ```

   To keep the compiled binary instead of running it directly, use `zeus build`:

   ```bash
   zeus build hello.zs -o hello
   ./hello
   ```

</Steps>

## Understanding the code

```zeus
console.log("Hello, World 👋")
```

- `console` — a global object available in every program, no import needed.
- `.log` — prints to stdout with a trailing newline, like JavaScript's `console.log`.
- Strings are full UTF-8, so emojis 🎉 work out of the box.

Zeus also provides `console.error` (stderr) and `console.info` (stdout):

```zeus
console.log("info message")
console.error("something went wrong")
console.info("another info message")
```

## Controlling the exit code

A program exits with code `0` by default. To return a specific exit code — for scripts, CI, or
error signaling — define an optional `main` function that returns `i32`:

```zeus
function main(): i32 {
  console.log("starting up")
  return 42   // becomes the process exit code
}
```

```bash
zeus run exit-code.zs
echo $?   # 42
```

Module-level code runs directly, so `main()` is never required:

```zeus
console.log("module-level code runs")
```

## A slightly bigger example

```zeus
class Greeter {
  public times: i32;

  constructor(t: i32) {
    this.times = t;
  }

  public greet(): void {
    let i = 0;
    while (i < this.times) {
      console.log("Hello!")
      i = i + 1;
    }
  }
}

let greeter = new Greeter(3);
greeter.greet();
```

```bash
zeus run greeter.zs
# Hello!
# Hello!
# Hello!
```
